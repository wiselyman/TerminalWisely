# TerminalWisely 0.0.8 UI 与交互设计规范

## 目标与边界

将全产品界面收敛为清晰、克制、信息密度适中的专业桌面工具；保持现有功能、数据行为、标签语义和主要操作路径。覆盖 Home、Hosts/SSH、Kubernetes、数据库、AI 聊天、文件预览、本地文件、桌面、设置、导航、菜单和弹窗。支持深浅主题及 macOS、Windows、Linux 的原生窗口差异。

## 设计原则

- 以语义颜色、4px 间距阶梯、统一字体层级、边框、焦点环、状态色和圆角作为共享基础；页面通过同一套 token 表达状态。
- 导航层级保持浅，侧栏服务于所在空间；空间切换、标签、分栏和窗口尺寸变化不丢失当前上下文。
- 工具栏、表格、表单、弹窗、空状态、提示、审批与错误反馈采用一致的结构和状态反馈；保留各工作台必要的信息密度。
- Home 是本机 Terminal 与本机聊天的并列工作区；Terminal 横跨左侧区域，聊天在右侧，分隔栏可拖动并可键盘调整。
- 窄窗口下优先重排或折叠次要信息；主要动作、焦点和当前选择始终可见，内容不被遮挡或横向溢出。
- 使用平台原生字体、标题栏和窗口控件差异，不仿制其他产品的品牌外观。

## 交互状态

所有共用控件需有静止、悬停、按下、选中、禁用、加载、成功、错误和键盘焦点状态；危险操作、审批、空数据与网络失败在发生操作的上下文附近反馈。复用现有本地化文案和业务反馈，不新增工作区能力。

## 视觉验收

Playwright 为代表性关键页面建立深色/浅色截图基线，采用固定 Chromium、视口、字体与测试数据。至少覆盖 Home、Hosts、Kubernetes、数据库、AI 聊天、文件预览、设置/弹窗。视觉断言配合既有交互 E2E，避免截图替代行为测试。检查键盘焦点可见性、代表性窄窗口溢出/遮挡，以及空间切换后主题和会话上下文保持。

## 评估矩阵

| 界面 | 现状发现 | 优先级与本轮方向 |
|---|---|---|
| 应用壳层/空间/标签 | 深色接近纯黑、浅色表面分层弱；顶栏活动空间与活动会话区分不明显；焦点环和分隔线强调色不一致。 | P0：统一语义色、标签层级、边框与焦点环；保留平台标题栏差异。 |
| Home 终端/聊天分栏 | Terminal 与聊天的背景明度落差过大；聊天输入卡片阴影偏重；分隔线在键盘聚焦时缺少统一反馈；窄窗口易挤压两栏。 | P0：舒缓终端/聊天边界，统一分隔栏与 composer，验证 1024px 和键盘缩放。 |
| Hosts/SSH | 保存连接、分组与工作区表面层级较多；连接列表选中和焦点容易混淆；连接中状态占据主画面但反馈对比度有限。 | P0：加强选中/焦点区别，统一共享工作台框架；保留连接中/断开/传输反馈。 |
| Kubernetes | 导航树、资源表和详情区域边框颜色来源不一；资源表密集但列标题和当前选择需加强。 | P0：统一共享工作台/表格边界与状态色，保留资源密度和操作顺序。 |
| 数据库工作台 | 数据库树、连接表单和结果表的视觉由多组样式拼接；表单焦点、结果状态和危险维护操作层级不一。 | P1：沿用紧凑表格密度，规范表单边框、表格表头和错误/审批状态。 |
| AI 聊天 | Home composer 的边框与阴影较重；输入区、工具状态、审批和流式状态的对比方式分散。 | P1：收敛输入卡片和状态语义，保持消息/轨迹信息密度及审批位置。 |
| 文件预览/本地文件 | 预览窗口的蓝色强调边框较强；本地文件工具栏和路径区与主工作台边界感不同。 | P2：预览改用中性表面边框，统一工具栏和路径导航表面。 |
| 桌面、设置、菜单、弹窗 | 桌面玻璃效果与其他工作台不同；设置/弹窗阴影、表面、焦点反馈尚未完全共享。 | P2：统一通用弹窗和桌面导航边界，不改变桌面场景的背景表达。 |

### 平台截图策略

当前仓库可本机生成的像素基线按 macOS Chromium runner 保存；其余系统字体、原生窗口与控件绘制会改变像素结果。Windows/Linux 继续运行主题 token、键盘焦点、窗口缩放与交互 E2E 合约；截图对比在相应原生 runner 维护各自基线后扩展。此分层避免跨系统字体差异产生误报，同时让核心布局与主题契约继续受 CI 检查。

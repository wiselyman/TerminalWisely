# MarkWisely Rich Export Design

## Intent

Add high quality HTML, PDF, and editable Word (`.docx`) exports from MarkWisely's formatting toolbar. Export is document conversion, not saving a Markdown copy; Markdown is not an export format.

## Goals

- Let users choose HTML, PDF, or Word from the existing Export toolbar action.
- Keep exported content legible and structured: document title, headings, paragraphs, emphasis, lists, quotes, code, links, and tables.
- Save HTML and DOCX through the native save dialog. PDF uses a hidden print document and the system print dialog so system fonts (including CJK fonts) and vector text are preserved.
- Preserve current editor content, current filename, host/local behavior, and autosave behavior.
- Provide localized format labels, errors, and completion feedback.

## Non-goals

- Do not add image conversion, PDF annotations, or page-layout editing in this change.
- Do not alter the editor toolbar's formatting controls or the source Markdown representation.
- Do not replace the system print dialog with rasterized screenshots.

## Approaches

1. **Structured DOCX plus system PDF printing (selected):** Build DOCX from parsed Markdown blocks, export a styled standalone HTML document, and print styled HTML to PDF using the platform's native print-to-PDF path. This preserves selectable text and uses installed fonts, including Chinese fonts. PDF destination is chosen in the system print dialog; HTML and DOCX use the app's native save dialog.
2. **Generate both PDF and DOCX in JavaScript:** A PDF library would need embedded CJK fonts and explicit pagination, increasing bundle size and font licensing/distribution work.
3. **Print for both formats:** This delegates good PDF output to the OS but does not create an editable Word document reliably.

## Interaction and output design

- Clicking the existing Export toolbar button opens a compact menu with HTML, PDF, and Word (.docx); there is no Markdown export entry.
- HTML and DOCX open the native save dialog with the correct extension and filter. Cancel has no side effects.
- PDF opens a print-ready view of the current editor text with clean page margins, readable line length, typography, headings, lists, tables, code blocks, and links. The system print dialog lets the user print or save as PDF.
- Print/render or file-write failures show an error toast and inline error; successful HTML/DOCX writes show the exported path. The PDF path is confirmed through the opened print dialog, not claimed as a completed disk write.
- Export uses the latest editor buffer, including text not yet autosaved, and does not modify the source document.

## Constraints

- Existing local/SSH document storage remains unchanged; exported output is written to the user's chosen local destination. DOCX binary writes use a narrowly scoped local filesystem command that decodes the generated bytes and writes only to the selected destination path.
- Only safe, print-oriented HTML is emitted. Markdown raw HTML must not execute in the print document.
- DOCX generation should preserve common Markdown structure and use appropriate heading, paragraph, list, quote, code, hyperlink, and table styling.

## Acceptance

- Unit tests cover Markdown-to-DOCX structure, escaping/safe PDF HTML, and print styles.
- Playwright covers export menu labels, HTML and DOCX export targets, PDF print document, cancellation, and failure feedback.
- Run hardcoding check and full repository suite before completion.

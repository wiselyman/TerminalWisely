# TerminalWisely 0.1.4 Release Plan

> **For agentic workers:** Execute the plan task-by-task using test-first steps. Do not send the development plan or implementation for Codex review.

**Goal:** Make EditorWisely a practical local text editor with a directory tree and multi-file tabs, route OS-opened local text files directly into a full-window EditorWisely document, and ensure OS-opened Markdown files display their document in MarkWisely.

**Architecture:** Keep document state in the existing target-scoped `editorWiselyStore` and `markWiselyStore`. Extend native file-open argument/event handling to route Markdown documents to MarkWisely and other supported plain-text documents to EditorWisely; both apps reuse the local Desktop target and existing maximized-window state. Add EditorWisely's directory tree inside its window, backed by existing local/remote filesystem APIs and scoped to the active Desktop target.

**Tech Stack:** React, TypeScript, Zustand, CodeMirror, Tauri/Rust, Vitest, Playwright.

**Spec:** User request for TerminalWisely 0.1.4; current behavior and constraints in `AGENTS.md`, `docs/HANDOFF.md`, and `docs/superpowers/plans/2026-11-24-markwisely-os-open-fill.md`.

## Global Constraints

- Preserve the repo's no-hardcoding rule: use generic file-kind classification and existing filesystem capabilities, without software-name allowlists or scenario-specific command rules.
- Maintain local/SSH target isolation for editor documents, filesystem navigation, and open-file events.
- Implement each item test-first: add the regression test, observe failure, implement the smallest change, then run that test layer.
- Update `docs/TEST_MATRIX.md` for the editor and native file-open coverage.
- Before calling 0.1.4 complete, run `node scripts/check-no-agent-hardcoding.mjs` and `./scripts/run-all-tests.sh` successfully.

## Review Focus

- Reopening a path already in an EditorWisely tab activates the existing tab and does not duplicate or replace its dirty buffer.
- Opening a directory entry and navigating to a parent/root never changes the active editor document until a file is selected.
- A local text file opened by the OS launches the local Desktop, opens the exact file, and presents EditorWisely maximized with its content visible.
- A local Markdown file opened by the OS presents that file in MarkWisely; opening MarkWisely without a path still shows its normal home screen.
- Unsupported, binary, oversized, or undecodable files produce the existing visible error state and do not become editable documents.

## 要保住的旧行为

- EditorWisely existing open, edit, autosave, explicit save, save-as, dirty-close confirmation, syntax highlighting, recents, and UTF-8/newline/BOM preservation continue to work.
- EditorWisely's existing document tabs remain target-scoped; reopening a path activates its tab, and a dirty document's in-memory contents are not replaced by a second read.
- The MarkWisely file picker, document tabs, autosave, outline, and local/SSH isolation remain unchanged for manual use.
- OS-opened Markdown paths continue to activate Home/local Desktop and maximize MarkWisely; the exact requested file is visible, and errors still use the existing toast.
- Local Files double-click, Edit & Preview, and Open with EditorWisely continue to open only the selected supported file.
- Opening either editor manually without a file continues to show its existing home/empty state.

## 架构

- `src/components/desktop/EditorWiselyWindow.tsx` and `.css`: add an editor-owned directory tree and selected-file navigation while retaining the current CodeMirror document pane, tabs, and status bar. Keep tree state/view behavior in a focused component/module if the window grows beyond a single responsibility.
- `src/stores/editorWiselyStore.ts` and focused `src/lib/editorWisely*` modules: retain document buffers and active tab by `DesktopTarget`; provide directory listing/navigation through existing filesystem APIs rather than embedding file I/O in tree rendering.
- `src-tauri/src/markdown_open.rs` plus its argument/event tests: generalize pending native-open paths from Markdown-only to supported text files while retaining generic content validation at read time. Route by the existing file-kind classification; do not add application-name or per-extension special-case allowlists.
- `src/App.tsx`: drain native-open paths, activate local Desktop, dispatch Markdown to MarkWisely and other text files to EditorWisely, and maximize the matching app after its document is opened.
- `src/stores/desktopStore.ts` and existing editor stores: reuse current open/maximize actions; do not introduce another window lifecycle mechanism.
- `src/lib/desktopTarget.ts`, local/remote filesystem API modules, `src/stores/editorWiselyStore.test.ts`, `src/App.homeTab.test.ts`, `e2e/home-local-terminal-chat.spec.ts`, native-open Rust tests, and `docs/TEST_MATRIX.md`: define target isolation, regression coverage, and test mapping.

## 设计

- EditorWisely opens with a resizable left directory tree and a main editing area. The tree starts at the local filesystem root for Home or the active workspace root for SSH; expanding folders navigates without replacing the open file. Selecting a text file opens or activates its document in a tab. Multiple files remain visible as tabs; closing one follows the existing dirty-document confirmation behavior.
- When a user chooses TerminalWisely to open a local plain-text file in the OS, the app opens Home/local Desktop, displays EditorWisely maximized across the available TerminalWisely desktop area, and shows that file as the active open document. Loading is shown in the editor pane; read/validation failure appears in the editor error area.
- When a user chooses TerminalWisely to open a local Markdown file, the app opens Home/local Desktop, displays MarkWisely maximized, and loads the requested Markdown document in its editing view. Loading and failure retain MarkWisely's existing feedback behavior. Launching MarkWisely manually without a path continues to show its home screen.
- The 0.1.4 release notes describe these editor and native-open changes in English and Chinese; product documentation remains aligned.

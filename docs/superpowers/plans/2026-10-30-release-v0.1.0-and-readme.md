# TerminalWisely v0.1.0 Release and README Plan

> **For agentic workers:** Follow this plan task by task. Steps use checkbox syntax for tracking.

**Goal:** Publish v0.1.0 after aligning release notes and bilingual product documentation with the shipped Home Desktop behavior.

**Architecture:** Keep the existing version metadata and tag-triggered GitHub Actions release workflow. Replace static version-tag claims in both READMEs with the dynamic GitHub Latest Release route, correct Home Desktop app descriptions, and archive the release notes/changelog before creating the release tag.

**Tech Stack:** Markdown, Node.js static smoke checklist, GitHub Actions, GitHub CLI.

**Spec:** User request in this conversation and the release procedure in `BUILD.md`.

## Global Constraints

- Release only the existing `0.1.0` source version; do not change application behavior or version metadata.
- Home Desktop documentation must reflect that its visible apps are Terminal, AI Local, and MarkWisely; Files, Browser, and Processes are omitted from Home Desktop.
- The README must not name a future fixed release tag before it exists; use GitHub's dynamic latest-release URL.
- Release v0.1.0 through `.github/workflows/release.yml` by pushing `v0.1.0` after the documentation commit is on `main`.

## Review Focus

- README latest-release links: assert both languages point to `/releases/latest` rather than a fixed tag.
- Home Desktop feature summaries: assert both languages do not claim Home Dock has Files, Processes, or Browser.
- Release notes: ensure both language sections reflect the same included behavior and exclude the omitted Home apps.
- Release workflow: verify the tag-triggered workflow can build and publish all configured platform assets and updater metadata.
- GitHub status: verify no v0.1.0 tag/release already exists before creating it, then watch the run through completion.
